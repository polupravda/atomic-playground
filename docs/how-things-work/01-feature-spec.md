# Interactive Atom & Chemistry Playground — handover specification

> Source of truth for the feature set. Stored verbatim from the handover
> discussion (2026-08-21). Reference features by ID (e.g. A01, P03, B04).
> Implementation status lives in [04-roadmap.md](04-roadmap.md).

This is a functional/educational specification rather than a
product-description table: the data model, UI states, animations, and
scientific rules should be inferable from it.

Baseline reference: PhET's *Build an Atom* already establishes that particles
affect **element identity, charge and mass**, and that the UI can switch
between atom representations including a cloud representation. PhET's teaching
material also explicitly uses the simulation to explore charge by changing
proton/electron counts.

## Recommended bonding scope

**Do not build a universal chemistry engine initially.** For V1, hard-code /
curate just these scenarios:

| Example             | Demonstrates                                         |
| ------------------- | ---------------------------------------------------- |
| **H + H → H₂**      | simplest electron sharing                            |
| **Na + Cl → NaCl**  | electron transfer, ions, attraction                  |
| **H + O + H → H₂O** | multiple covalent bonds, lone pairs, molecular shape |
| **C + 4H → CH₄**    | carbon's four bonding relationships                  |
| **C + 2O → CO₂**    | double bonds; Version 2 if needed                    |

This is preferable to pretending that a simple rule can determine whether any
arbitrary pair of elements will "bond." Real chemistry depends on bonding
type, oxidation states, molecular structure, energetics, conditions and more.
PhET itself separates its atom-building and molecular-shape/building
experiences into different simulations rather than pretending they are one
simple rule.

## The core animation language

**Four visual motions recur throughout the entire application:**

1. **Particle enters/leaves** → something about the atom changes.
2. **Particle moves between atoms** → electron transfer / ionic bonding.
3. **Electron density overlaps** → electron sharing / covalent bonding.
4. **Objects attract or repel** → electromagnetic interaction.

This gives the application a consistent visual vocabulary instead of every
concept having an unrelated animation.

The **shell → cloud transformation (A13/A14) is the signature animation**: the
child sees the same electron representation gradually change from a simplified
orbit into a probability cloud, rather than being told that "the atom has
another model." This is where the playground goes beyond existing simulations.
